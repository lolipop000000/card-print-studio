# 클라우드 저장과 공용 공유 설계안

작성일: 2026-10-21
대상: 카드 작업실(card-print-studio) v1.5.x 이후
상태: 대화로 요구 확정, 구현자 관점 검토(1회) 반영, 사용자 문서 검토 대기
표기: "(확정)"은 사용자가 정한 것, "(내 판단)"은 설계자가 정한 기본값이다. 내 판단은 사용자가 바꿀 수 있다.

## 왜 만드는가

친구 3명(최대 8명)이 함께 카드게임 결과물을 만든다. 지금은 각자 PC 폴더에 저장하고 파일을 주고받는다. 이번 작업으로 세 가지를 바꾼다.

- 작업을 **클라우드에 저장**해서 어느 PC에서든 이어서 작업한다.
- 공개한 결과물을 **공용 저장소**에서 서로 보고 가져다 쓴다. 대상은 카드·덱과 에셋(이펙트 템플릿, 이미지, 카드 서식, 키워드)이다.
- 나중에 만들 **게임이 공개된 결과물을 한 번에 다운로드**한다.

**모르는 사람이 들어와서 마구 만들거나, 믿었던 멤버가 어느 날 공격하는 일**이 없어야 한다. 사용자는 실제로 "연기하다가 딱 랜섬웨어를 보내는" 경우를 걱정했다.

## 사용자와 권한 (확정)

| 구분 | 할 수 있는 것 |
|---|---|
| 로그인 안 한 사람, 로그인했지만 승인 안 된 사람 | 공개된 결과물 **보기만** 가능. 사본 만들기, 올리기, 내려받아 활용하기는 불가 |
| **준멤버** (관리자가 `trial`로 지정한 계정, 확정) | 멤버와 **같은 기능**(클라우드 저장, 공개, 사본, 에셋 공유). 단 **카드 10장**까지 |
| **멤버** (관리자가 승인한 Google 계정) | 내 작업 클라우드 저장, 공개·비공개 전환, 공개된 것을 **사본으로 가져와** 고치기, 내 것 수정·삭제, 에셋 공유. 카드 120장까지 |
| **관리자** (서버 주인 = 사용자 본인) | **Supabase 대시보드에서** 멤버 승인·해제. 문제 있는 게시물 삭제·복구 |

- 로그인은 **Google 로그인만** 지원한다.
- 원본은 **올린 멤버 본인만** 수정·삭제한다. 다른 멤버의 원본을 직접 고치는 기능은 없다.
- 관리자 화면은 작업실 안에 만들지 않는다. 승인은 대시보드에서 직접 처리한다.

## 확정된 동작

1. **작업 전체를 클라우드에 저장**한다. 덱, 카드, 그림 원본과 레이어, 키워드, 이펙트, 카드 서식이 모두 대상이다.
2. 새 작업은 **비공개**가 기본이다. **"공개"를 눌렀을 때만** 공용 목록에 올라간다.
3. **저장은 두 단계로 나눈다** (확정):
   - **자동 저장**: 편집하면 클라우드의 **내 초안**에만 저장한다. 나만 보고, 버전 기록을 남기지 않으며, 실시간 알림도 보내지 않는다.
   - **저장 버튼(Ctrl+S)**: 초안을 저장본으로 확정한다. 공개한 작업이면 **공개본에도 즉시 반영**되고, 버전 기록을 하나 남긴다. 별도의 "공개본 업데이트" 단계는 없다.
   - 그래서 반쯤 고친 상태는 공개 목록이나 게임에 나가지 않는다.
4. **실시간**은 공개 목록 갱신에만 쓴다. 멤버가 공개하거나, 공개본을 저장하거나, 삭제하면 다른 사람 목록에 바로 반영된다. **같은 카드를 여럿이 동시에 편집하는 기능은 만들지 않는다.**
5. 다른 사람의 공개 작업을 고치려면 **사본**을 만든다. 사본에는 출처(원본 작업 ID, 원본 소유자)를 기록한다.
6. **멤버는 카드 120장, 준멤버는 카드 10장**까지 저장한다(확정). 비공개와 공개를 합친 수이고, 휴지통에 있는 것은 세지 않는다. 준멤버의 10장은 모두 공개할 수 있다. 준멤버를 멤버로 올리면 한도만 120장으로 바뀌고 데이터는 그대로다. 멤버를 준멤버로 내릴 때 이미 10장을 넘었다면 지우지 않고, **10장 이하가 될 때까지 새 카드 추가와 사본 만들기만 막는다**(내 판단).
7. 작업실은 **웹 주소로 열어서 쓴다**(GitHub Pages). 지금의 "파일로 내보내기·불러오기"는 백업용으로 남긴다.
8. 공유할 에셋은 **지금 작업실에 있는 것**으로 한정한다: 이펙트 템플릿(내 이펙트), 이미지 에셋(공용 이미지 보관함), 카드 서식(내 카드 서식), 키워드. 다른 종류는 나중에 추가한다.
9. 처음 로그인한 멤버는 **PC에 있는 작업을 클라우드로 한 번에 올릴 수 있다.**
10. **게임은 공개된 것만** 다운로드한다. 게임 능력 규칙은 이번 범위가 아니다.
11. 공개 목록에는 작성자의 **닉네임**만 표시한다(확정). Google 실명과 이메일은 다른 사람이 읽을 수 있는 곳에 저장하거나 표시하지 않는다.
12. 로그인한 멤버는 **클라우드가 기본 저장 위치**다(내 판단, "작업 전체를 클라우드"에서 나옴). 연결한 PC 폴더에는 더 이상 자동 저장하지 않는다. 폴더와 파일은 가져오기·내보내기(백업)로만 쓴다. 로그인하지 않았거나 file://로 연 경우에는 지금처럼 폴더 저장을 쓴다.
## 목표 · 비목표 · 반드시 피할 것

**목표**
- 멤버 3~8명이 Supabase 무료 플랜 안에서 저장, 공개, 사본, 실시간 목록, 게임 다운로드를 쓸 수 있다.
- 모든 권한 규칙은 **서버에서 강제**한다. 작업실 화면에서 버튼을 숨기는 것만으로 막지 않는다.

**비목표**
- 동시 편집, 작업실 안의 관리자 화면, 댓글이나 좋아요, 게임 능력 규칙, 유료 플랜 전제 기능, 웹GL 서버 렌더링

**반드시 피할 것** (기술적으로 동작해도 실패로 본다)
- 승인 안 된 계정이 무엇이든 쓰기에 성공하는 것
- 한 멤버가 다른 멤버의 데이터를 바꾸거나 지울 수 있는 것
- 업로드한 파일이 다른 사람의 작업실이나 게임에서 코드로 실행되는 것
- 관리자 비밀키(service role key)가 작업실 코드나 GitHub Pages에 들어가는 것
- 실수나 악의로 지운 데이터를 되돌릴 방법이 없는 것

## 제약

- **Supabase 무료 플랜**: DB 500MB, 파일 저장소 1GB, 월 다운로드 5GB(+캐시 5GB), 업로드 파일 최대 50MB, Realtime 동시 접속 200, 무료 프로젝트 2개, **1주일 동안 활동이 없으면 일시정지**.
- 지금 카드 한 장 파일은 그림이 base64로 들어 있어 **평균 약 1MB, 최대 1.4MB**이다(2026-10-21 실측). 그대로 3명이 120장씩 채우면 약 360MB다.
- 기존 형식인 프로젝트 v1(`format:'card-print-studio'`)과 카드 한 장 v1(`card-print-studio-card`), 그리고 `validateProject`의 엄격한 검증을 유지한다.
- 작업실은 단일 HTML 빌드다. 새 버전 받기(update.json)와 오프라인 사용 흐름이 이미 있다.

## 구조

### 호스팅과 로그인
- `dist/`를 GitHub Pages(`https://lolipop000000.github.io/card-print-studio/`)로 게시한다. Supabase Auth의 Google 공급자를 쓰고, 리디렉션 주소로 이 Pages 주소를 등록한다.
- **내 판단:** file://로 연 작업실도 계속 동작하게 둔다. 이때 클라우드 기능은 "웹 주소에서 열어 주세요" 안내와 함께 꺼 둔다. 기존 업데이트 기능의 다운로드 흐름과도 맞다.
- 작업실에는 Supabase **공개(anon) 키만** 넣는다. 공개 키는 노출되어도 되며, 보안은 아래의 서버 규칙으로 지킨다.

### 데이터 (Postgres)
**내 판단:** 표 구조는 다음을 기준으로 하고, 세부 열과 인덱스는 구현자가 정한다.

- `profiles`: `id`(= auth 사용자), `nickname`, `status`(`pending` | `trial` | `member` | `revoked`), 만든 날짜. Google 첫 로그인 때 트리거로 `pending` 행을 만든다. Google 실명과 이메일은 이 표에 복사하지 않는다(auth 내부에만 있음). **관리자는 대시보드 Table Editor에서 `status`를 `member`로 바꿔 승인**하고, `revoked`로 바꿔 해제한다. 대시보드에서 누구인지 알아볼 때는 auth 사용자 목록의 이메일을 본다.
  - 닉네임은 첫 로그인 때 정하고, 2~20자에 멤버 사이에서 중복되지 않는다. 나중에 바꿀 수 있다(`set-nickname` 함수). 다른 사람과 anon에게는 `id`와 `nickname`만 보이는 뷰를 연다.
- `works`: 덱(프로젝트) 단위의 작업. 열은 `id`, `owner`, `title`, `visibility`(`private` | `public`), `data`(jsonb, 저장 버튼으로 확정한 **저장본**, 공개 대상), `card_count`, `version`(정수, 저장 버튼마다 증가), `source_work_id`, `source_owner`, `updated_at`, `deleted_at`이다.
- `work_drafts`: 자동 저장한 **초안**. 열은 `work_id`, `owner`, `data`, `card_count`, `saved_at`이다. **본인만 읽고 쓰는 별도 표**로 둔다. `works`의 열로 두면 Realtime 변경 알림이 행 전체를 보내면서 공개 작업의 초안이 다른 사람에게 새어 나갈 수 있어서 분리한다(내 판단). 카드 수 한도는 저장본과 초안 중 큰 값으로 센다.
  - 카드 한 장 공유는 카드 1장짜리 작업으로 저장한다. 기존 카드 한 장 파일과 같은 개념이다.
- `shared_assets`: 에셋. `kind`(`effect_template` | `image` | `card_template` | `keyword`), `owner`, `title`, `visibility`, `data`(jsonb), `version`, `source_*`, `deleted_at` 열을 둔다.
  - **내 판단, 에셋은 스냅샷이다.** 덱 안의 이펙트 템플릿, 카드 서식, 키워드를 "에셋으로 공유"하면 그 순간의 내용을 복사해서 별도 행으로 저장한다. 원본 덱과 실시간으로 연결되지 않는다. 고친 걸 다시 공유하려면 같은 행에 저장 버튼으로 덮어쓴다.
  - 형식: 이펙트 템플릿, 카드 서식, 키워드는 프로젝트 안의 `visualEffectPresets`, `cardTemplates`, `keywords` 항목 형식을 쓴다. **이미지는 공용 이미지 보관함의 항목 형식**(`src/model/asset-library.js`)을 쓴다.
  - 의존 이미지: 템플릿이나 키워드 아이콘, 이펙트 스프라이트가 이미지 ID를 참조하면, 그 이미지를 blob 참조로 **함께 담아** 저장한다. 가져갈 때 ID를 새로 매긴다(기존 카드 서식 적용, 카드 한 장 가져오기의 ID 재매핑 방식과 같음).
  - 가져가기: 이펙트 템플릿, 카드 서식, 키워드는 **지금 열린 덱**에 추가한다. 이미지는 **내 이미지 보관함**에 추가한다.
  - **내 이미지 보관함도 클라우드에 저장한다**("작업 전체"). 보관함의 각 이미지는 `kind='image'`인 비공개 `shared_assets` 행이고, 공개를 누르면 공용 목록에 올라간다.
- `work_versions`: **저장 버튼으로 확정할 때마다** 직전 저장본을 보관한다. **작업마다 최근 20개**를 남긴다(내 판단). 자동 저장한 초안은 버전을 만들지 않는다.
- `audit_log`: 모든 쓰기 요청을 기록한다(누가, 무엇을, 언제, 결과).

### 이미지 (Storage)
- 클라우드 형식에서는 base64 그림을 **내용 해시(SHA-256) 참조**로 바꾼다. `assets[id].dataUrl`과 그림 레이어의 `png`가 대상이다. 실제 이미지는 `blobs` 버킷의 `{sha256}` 경로에 한 번만 저장한다. 그래서 같은 그림을 여러 카드나 사본이 써도 한 번만 저장된다.
- **내 판단:**
  - 그림 레이어와 원본은 편집 가능한 원본이므로 **무손실**로 둔다. 무손실 WebP가 PNG보다 작으면 WebP를 쓰고, 아니면 PNG를 쓴다.
  - 작업실에서 불러올 때는 다시 base64 `dataUrl` 형식으로 되돌린다. 그래서 기존 편집, 렌더링, 검증 코드는 바꾸지 않는다.
- 이미지 용량 제한은 **1인당 고유 바이트 기준 150MB**다(내 판단, 카드 120장 × 평균 1MB 이상).
- **내 판단:** `blobs` 버킷은 **공개 읽기**로 둔다. 경로가 256비트 해시라 추측할 수 없고, 게임이 쉽게 받을 수 있다. 대신 비공개 작업의 그림도 해시를 아는 사람은 볼 수 있다는 한계가 있다. 이 한계를 받아들이지 않으면 서명 URL 방식으로 바꾼다.

### 쓰기 경로 — 전부 서버 함수(Edge Function)를 통과
- 클라이언트의 **직접 INSERT, UPDATE, DELETE와 Storage 업로드는 RLS와 버킷 정책으로 전부 거부**한다. 모든 쓰기는 Edge Function이 service role로 수행한다.
- 함수 목록: `save-draft`, `save-work`, `set-visibility`, `copy-work`, `delete-work`, `restore-work`, `upload-blob`, `save-asset`, `copy-asset`, `delete-asset`, `import-local`, `set-nickname`. 정확한 나눔과 이름은 구현자가 정한다.
- `save-draft`는 `work_drafts`만 바꾼다. 실시간 알림, 버전, 게임 목록에 영향을 주지 않는다. `save-work`는 초안(또는 보낸 내용)을 `works.data`로 확정하고, 버전을 남기고, 초안 행을 지운다.
- 각 함수가 공통으로 하는 일:
  1. JWT를 확인하고 `profiles.status`가 `member` 또는 `trial`인지 확인한다. 아니면 403. 등급별 한도는 함수에 하드코딩하지 않고 `tier_limits` 표(등급, 카드 수, 이미지 바이트)에서 읽는다. 관리자가 대시보드에서 숫자를 바꿀 수 있게 하기 위해서다(내 판단).
  2. 대상 행의 `owner`가 요청자인지 확인한다(복사는 원본이 `public`인지 확인).
  3. **기존 작업실 검증 코드(`validateProject`, `validateVisualEffects` 등, 순수 JS)를 함수에 그대로 번들해서** 클라우드 형식을 되돌린 내용을 검증한다. 작업실과 서버가 같은 규칙을 쓴다.
  4. 한도를 확인한다: 카드(멤버 120장, 준멤버 10장), 이미지(멤버 150MB, 준멤버 15MB, 내 판단), 요청 크기, 시간당 횟수(내 판단). 시간당 횟수는 **확정 저장·공개·복사·삭제 등 60회, 초안 자동 저장 240회(같은 작업은 30초에 한 번까지), blob 업로드 200개**다. `import-local`은 아래 별도 규칙을 따른다.
  5. `audit_log`에 기록한다.
- `upload-blob`: 파일 앞 바이트(매직 넘버)로 **PNG, JPEG, WebP만** 허용하고, 크기를 확인한 뒤 SHA-256이 경로와 일치하는지 검증한다. SVG, GIF, HTML 등 나머지는 모두 거부한다.
- 저장 충돌: `save-work`와 `save-draft`는 클라이언트가 보낸 `version`과 초안의 `saved_at`이 서버와 다르면 거부한다. 다른 탭이나 PC에서 먼저 저장한 경우 작업실은 덮어쓰지 않는다. "서버 내용 불러오기" 또는 "내 내용을 새 사본으로 저장" 중에서 고르게 한다.
- 오프라인(내 판단): 클라우드 저장이 실패해도 기존 IndexedDB 자동 복구가 내용을 보관한다. 연결되면 초안 저장을 다시 시도하고, 그때 충돌하면 위 선택지를 띄운다.

### PC 작업 일괄 올리기 (`import-local`, 내 판단)
- 대상: 연결한 폴더의 덱 파일과 카드 한 장 파일, 그리고 내 이미지 보관함이다. 목록을 보여 주고 **사용자가 올릴 것을 체크**한다. 기본은 전부 체크다.
- 올리기 전에 카드 수와 이미지 용량을 미리 계산한다. 한도(120장, 150MB)를 넘으면 넘는 양을 보여 주고 일부를 빼게 한다. **한도 자체를 예외로 풀어 주지는 않는다.**
- 시간당 횟수 제한 대신 전용 제한을 쓴다: 계정당 하루 1회 실행, 한 번에 덱 50개, blob 2,000개까지다. 같은 해시의 blob은 건너뛴다.
- 올라간 작업은 모두 **비공개**로 시작한다.

### 읽기 경로
- RLS SELECT 규칙:
  - `visibility='public' AND deleted_at IS NULL`인 행은 누구나(anon 포함) 읽을 수 있다.
  - 본인 행(`owner = auth.uid()`)은 휴지통을 포함해 본인이 읽을 수 있다.
- 작업실은 불러온 내용을 다시 **`validateProject`로 검증한 뒤에만** 연다. 글자는 지금처럼 텍스트로만 그린다.
- **확정된 규칙과의 관계:** 승인 안 된 사람은 "보기만" 가능하다. 그래서 작업실은 이들에게 **사본 만들기와 파일 내려받기 버튼을 주지 않는다.** 다만 공개 데이터는 공개 API로 읽을 수 있으므로, 화면 밖에서 데이터를 복사하는 것까지 기술적으로 막지는 않는다. 서버에 쓰는 행위는 모두 막는다.

### 실시간
- Supabase Realtime의 Postgres 변경 구독으로 `works`와 `shared_assets`의 공개 행 변경(추가, 수정, 삭제, 공개 전환)을 받아 공용 목록을 갱신한다. `work_drafts`는 구독 대상에 넣지 않는다.
- **검증 필요:** Realtime이 RLS를 지켜서 비공개 행과 다른 사람의 초안을 절대 보내지 않는지 권한 행렬 검사에 포함한다. 공개에서 비공개로 바꿀 때 다른 사람 목록에서 사라지는 알림도 확인한다.

### 게임 다운로드
- 공개 목록 함수 `export-manifest`(읽기 전용)가 공개 작업과 에셋의 `id`, `kind`, `version`, `updated_at`, 내용 해시, 참조 blob 해시를 돌려준다.
- 게임은 이전에 받은 목록과 비교해서 **바뀐 작업과 아직 없는 blob만** 받는다. 월 다운로드 5GB를 지키기 위해서다.
- 게임도 받은 데이터를 **데이터로만** 다루고 같은 검증 규칙을 적용한다. 목록 형식은 버전 필드를 포함해 이 문서 이후에도 호환되게 한다.

### 삭제·복구·백업
- 삭제는 `deleted_at`만 기록한다(**휴지통 30일**). 30일이 지나면 예약 작업으로 영구 삭제하고, 어떤 작업도 참조하지 않는 blob을 정리한다.
- 관리자는 대시보드나 SQL로 `deleted_at` 해제와 `work_versions` 되돌리기를 할 수 있다. 작업실의 "휴지통"에서는 본인 것만 복구한다.
- **매일 백업**: GitHub Actions 예약 작업이 `pg_dump`와 새 blob을 **비공개 GitHub 저장소**에 저장하고 30일치를 보관한다. 접속 정보는 Actions secret에 둔다. 이 작업은 프로젝트를 활성 상태로 유지하는 효과도 있을 것으로 본다(구현자가 확인).
- 복구 훈련: 백업으로 빈 프로젝트를 복원하는 절차를 문서화하고 한 번 실행해 본다.

### 보안 체크리스트
- 관리자 Google 계정과 Supabase 계정에 **2단계 인증을 필수**로 건다.
- service role key는 Edge Function 환경 변수와 GitHub Actions secret에만 둔다.
- GitHub Pages HTML에 **CSP**를 넣는다. `connect-src`는 Supabase 프로젝트 도메인과 기존 업데이트 주소만 허용하고, `object-src 'none'`을 둔다. 외부 스크립트는 없다.
- 모든 문자열 길이와 JSON 깊이를 서버 함수에서 제한한다. 기존 `safeJson`과 같은 프로토타입 오염 차단도 적용한다.
- 승인 해제(`revoked`)는 다음 요청부터 즉시 쓰기를 막는다. 해제된 사람의 공개 작업은 관리자가 비공개로 바꾸거나 삭제할 수 있다.

## 작업실 화면 (내 판단, 구현자가 다듬음)
- 상단에 **Google 로그인** 버튼과 상태 표시(승인 대기 / 멤버)를 둔다.
- **클라우드** 창의 탭: 내 작업 / 공개 목록 / 에셋 / 휴지통. 공개 목록은 실시간으로 갱신하고 작성자 이름을 표시한다.
- 편집하면 초안을 자동 저장하고, **저장 버튼(Ctrl+S)**으로 확정한다. 상태는 "초안 저장됨 / 확정 저장됨 / 저장 중 / 실패 · 다시 시도"로 구분해서 표시한다. 확정하지 않은 초안이 있으면 "공개본과 다름" 표시를 보여 준다.
- 첫 로그인 때 닉네임을 정하는 창을 띄우고, 설정에서 바꿀 수 있게 한다. 공개 목록에는 닉네임만 표시한다.
- 공개·비공개 전환, 사본 만들기, 삭제와 복구 버튼을 둔다.
- 처음 로그인한 멤버에게 "PC에 있는 작업 올리기"를 제안한다.
- 승인 대기 상태라면 "관리자 승인 후 저장과 공유를 쓸 수 있어요"라고 안내한다.

## 관리자 운영 절차 (문서로 함께 제공)
- 새 멤버 승인: 대시보드 → Table Editor → `profiles` → 해당 행의 `status`를 `member`(정회원) 또는 `trial`(준멤버, 카드 10장)로 변경
- 등급별 한도 바꾸기: `tier_limits` 표의 숫자 수정
- 멤버 해제, 게시물 숨기기와 삭제, 휴지통 복구, 버전 되돌리기, 백업 복원 절차
- 일시정지된 프로젝트를 다시 켜는 방법

## 검증
- **권한 행렬 검사**: anon, pending, trial, member A, member B, revoked가 모든 표와 함수에 대해 읽기, 쓰기, 수정, 삭제, 복사를 시도한다. 기대한 성공과 실패를 자동으로 확인한다(로컬 Supabase 또는 별도 테스트 프로젝트에서).
- **악성 입력 검사**: 확장자를 위장한 SVG/HTML, 손상된 이미지, 거대한 JSON, `__proto__` 키, 허용 범위 밖 값, 다른 사람 해시 경로 덮어쓰기가 모두 거부되는지 확인한다.
- **한도 검사**: 멤버의 121번째 카드, 준멤버의 11번째 카드(사본 만들기와 PC 일괄 올리기 포함), 이미지 용량 초과, 시간당 횟수 초과가 거부되는지 확인한다. 멤버에서 준멤버로 내려간 계정은 기존 카드를 유지한 채 새 카드만 막히는지 확인한다.
- **왕복 검사**: 로컬 프로젝트 → 클라우드 형식 → 저장 → 불러오기 결과가 원래 프로젝트와 같은지 확인한다(그림 바이트 포함).
- **실시간 검사**: A가 공개하면 B의 목록에 반영되는지 확인한다.
- **충돌 검사**: 두 탭에서 저장하면 늦은 쪽이 거부되고 안내되는지 확인한다.
- **삭제·복구 검사**: 휴지통, 30일 정리, 버전 되돌리기를 확인한다.
- **백업 검사**: 백업에서 복원했을 때 작업과 이미지가 같은지 확인한다.
- **게임 목록 검사**: 바뀐 것만 받는지 확인한다.
- 기존 작업실 검사(오프라인 file:// 흐름 포함)가 모두 그대로 통과해야 한다.

Edge Function의 나눔과 이름, 표의 세부 열과 인덱스, 클라우드 형식의 정확한 키 이름, 자동 저장 간격, 화면 배치와 문구, 로컬 테스트 환경(Supabase CLI 등), 백업 저장 형식.
