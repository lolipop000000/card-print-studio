# 모바일 연속 입력 수정 — 1.6.6

입력할 때 편집창 전체를 교체하면서 모바일 입력기의 연결이 끊어졌습니다. 같은 문서·카드·선택 대상의 입력칸과 부모 노드를 유지하고, 저장과 실행 취소 기록은 즉시 반영하면서 화면 갱신을 140ms로 묶습니다. 다른 입력칸에서 아직 확정하지 않은 글자도 보존합니다. 숨겨진 카드 목록·캔버스·A4 미리보기는 다시 그리지 않고 해당 화면을 열 때 최신 내용을 반영합니다.

## 검증

- 수정 전: 같은 입력칸인지 확인하는 검사가 실패했고 입력 중 blur가 발생했습니다. 한글 조합 중 저장 상태 알림으로 입력칸이 교체되는 상황도 재현했습니다.
- 리뷰에서 발견한 숨겨진 A4 렌더링은 17글자 입력에 17회 갱신됐으며, 수정 후 0회입니다. 다음 입력칸의 미확정 글자가 사라지는 상황도 실패하는 검사로 재현한 뒤 수정했습니다.
- 기본·관련 검사 **583개**, 최종 입력 회귀 **6개** 통과. 회귀 범위는 연속 제목·설명 입력, 한글 조합, 즉시 저장, 숨겨진 미리보기, 빠른 입력칸 전환, 실행 취소·카드 전환·문서 불러오기·종료, PC 미리보기 갱신 묶기입니다.
- 기존 모바일 360/390px 화면, 터치 조작, 스킬 이름 참조, 제목 키워드, 글자 이펙트, JSON 업로드, A4 배치 검사도 포함했습니다.
- 최초 종합 실행의 새 검사 한 개는 스크립트로 `.value`만 바꿔 실제 브라우저의 `change`가 발생하지 않았습니다. 실제 `fill`과 Tab 입력으로 정리한 뒤 입력 회귀 6개를 재실행해 모두 통과했습니다. 나머지 코드는 바뀌지 않았으며 원래 로그는 유지했습니다.
- 독립 코드 리뷰의 중요한 지적 두 건을 재현·수정했고 재검토에서 남은 중요한 지적은 없었습니다.

`artifacts/qa/verify-mobile-typing.mjs`는 두 실행의 결과와 검사한 HTML 해시를 대조해 `mobile-typing-release-gate.json`에 요약합니다. 원본 결과는 `mobile-typing-final.log`, 최종 회귀 결과는 `mobile-typing-regressions.log`입니다.
