## 발견한 문제와 조치

1. **GPU 경계 샘플링:** 수직·수평에 가까운 방향성 흐림에서 정수 셀과 보간 가중치의 반올림이 달라 한쪽 표본이 사라지는 현상을 실제 GPU에서 재현했습니다. 가중치를 같은 셀에서 빼서 계산하도록 고쳤습니다. 공유 계산을 점검해 아주 작은 안쪽 그림자 이동과 침식 노이즈·소수 흐림 반경도 같은 원칙으로 처리합니다. 기존 엄격한 흐림 기준, 방향 33개·그림자 21개 조합을 통과했고 독립 리뷰의 방향성 500개 추가 조합도 알파·premultiplied 색 1 이내였습니다.
2. **복구 완료 표시:** 새 그림 적용 후 이전 복구본의 완료 표시가 대기 시간 동안 남아 빠른 재진입이 오래된 복구본을 읽는 문제를 재현했습니다. 변경마다 이전 완료 세대를 무효화하고 즉시 대기로 알립니다. 이전 쓰기의 늦은 완료도 구별하며 새 실패 검사와 실제 브라우저 재검사를 통과했습니다.
3. **검사 환경:** 과거 소프트웨어 래스터의 네 해시는 별도 CPU 페이지에서 그대로 유지합니다. 생산 GPU 경로는 독립 네이티브 합성 기준과 비교합니다. 인위적 GPU 복구 요청은 [명세](https://registry.khronos.org/webgl/extensions/WEBGL_lose_context/)에 맞게 손실 이벤트 뒤로 미뤘습니다. 그림의 200%·800% 검사는 초기 배치 완료와 실제 표시 크기를 확인한 뒤 기존 픽셀 불일치 0개·원본 동일 기준을 유지합니다.
4. **스프라이트 관찰:** 최초 전체 실행의 PNG 문자열 불일치 한 번은 추가 50회에서 재현하지 못했고 원인은 확정하지 못했습니다. PNG 인코딩만의 문제로 단정하지 않습니다. 고정 ID·전체 실패 자료를 보관하고 크기와 디코딩한 RGBA 전체가 정확히 같아야 통과하도록 검사합니다. 다른 시간은 다른 픽셀이 나와야 하며 기존 두 PDF 비교도 유지합니다. 이 관찰 때문에 생산 렌더 동작을 바꾸지는 않았습니다.

색수차의 컬러 프린지는 네이티브 틴트 양자화와 소수 위치 샘플링을 유지해 자동 어두운 글자·명시적 프린지 16개 조합이 CPU와 정확히 일치합니다. 입자 질감은 업로드 좌표의 정수·소수를 분리해 기존 작업 원점·투명 여백의 엄격한 동일 픽셀 회귀를 통과했습니다.

네이티브 래스터와 소프트웨어의 알파/premultiplied 색 최대 허용 한도는 그라데이션 0/1.4, 기본 흐림 3/3.2, 침식 0/0, 하프톤 0/1.1입니다. 측정값은 각각 0/1.353, 3/3.169, 0/0, 0/1.094였습니다. 흰색·어두운 배경과 8배 경계 확대에서 검은 매트·색 번짐·클리핑 이상은 보이지 않았습니다. 같은 생산 경로의 미리보기·출력 픽셀 일치 기준은 유지합니다.

미지원 GPU·부동소수점 대상 미지원·할당 실패·작업 한도 초과·연결 손실·복구를 검사했습니다. 처리 중 첫 draw·마지막 draw·읽기 직후 손실 모두 완전한 CPU 결과를 냈고 복구 뒤 GPU를 재개했습니다. 성공한 필터 뒤 혼합 읽기에 실패해도 완전한 CPU 혼합을 내고 대체 사용을 기록합니다. 공용 컨텍스트 하나·프로그램 최대 40개·작업 텍스처 최대 128 MiB를 사용하며 기존 블룸 컨텍스트는 별도입니다.

## 성능과 GPU 사용 범위

블룸은 Canvas2D에서 읽은 픽셀을 CPU로 계산합니다. WebGL/WebGPU 전용 블룸을 구현하거나 GPU 가속 사용을 검증한 것으로 보지 않습니다. 별도 QA 브라우저에서 하드웨어 어댑터를 얻을 수 있었던 사실도 작업실이 GPU를 활용한다는 증거로 쓰지 않습니다.

같은 실제 Edge의 7회 측정 중간값입니다. 개별 블룸 처리 시간이며 작업실 전체 프레임 속도는 아닙니다. 밀집 이미지에서는 개선 폭이 작습니다.

| 검사 장면 | 기존 | 개선 | 비율 |
| --- | ---: | ---: | ---: |
| 작은 발광 영역 · 150 DPI | 33.2 ms | 8.0 ms | 4.15배 |
| 작은 발광 영역 · 300 DPI | 179.7 ms | 35.2 ms | 5.10배 |
| 넓은 발광 영역 · 300 DPI | 150.6 ms | 136.6 ms | 1.10배 |

136개 조합에서 최적화 전과 RGBA가 정확히 일치했습니다. 멈춘 이펙트의 완성 이미지는 임시 마스크와 분리해 최대 64 MiB·128개까지 최근 사용 순서로 보관합니다. 네 기술 제목의 8개 효과와 독립 효과 11개가 이후 프레임에서 재합성 0회였으며, 새 렌더와 픽셀·진단·선택 영역이 일치했습니다. 선택 재생에서도 인쇄 시각의 출력은 전체 재생을 고정한 300 DPI 이미지와 일치합니다.

## 저장과 비동기 작업 검증

폴더 저장 실패 후 다시 실행해도 초안을 복구합니다. 실제 IndexedDB와 복제된 네이티브 폴더 핸들을 사용해 원래 폴더 식별, 외부 파일 변경 충돌, 성공한 재시도의 복구 메타데이터 해제와 명시적 초안 버리기를 검증했습니다. OS 폴더 선택 경계는 대체했으며 브라우저 파일 저장은 실제 OPFS로 실행했습니다.

이미지를 고르는 동안 덱·대상·키워드·이펙트 레이어가 바뀌거나 편집창이 닫히면 이전 작업을 다른 대상에 붙이지 않습니다. 보관함에서 삭제해도 이미 카드·키워드·이펙트에 복사한 그림은 휴대용 JSON에 남습니다.

독립 리뷰에서 찾은 재시작 초안 누락, 최초 읽기·명시적 다시 읽기 중 창 재열기, 임시 마스크 캐시 교체에 따른 재계산을 실패 재현 후 수정했습니다. 다시 읽기와 저장 완료는 현재 목록과 저장 기준에 함께 반영하므로 예전 목록으로 외부 변경을 덮지 않습니다. 최종 독립 재검토의 저장소·UI 33/33, 캐시·선택 재생 8/8 및 추가 300 DPI 비교가 통과했으며 검토 범위에 남은 확인된 문제는 없습니다.

실제 프린터의 급지·앞뒤 정합과 펜 하드웨어 검사는 포함하지 않았습니다. 사용자의 열린 작업 탭은 새로고침하지 않습니다.
