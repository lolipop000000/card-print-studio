# 구현 중 판단한 사항

계획 실행 기록의 `Ruling:` 35개를 결정한 순서대로 옮겼다. 부록 A SQL 원문과 부록 B 권한 기준은 유지했다. 운영 반영은 사용자 확인 전까지 대기한다.

| 순서 | 판단과 이유 | 영향·틀렸을 때 비용 |
| --- | --- | --- |
| 1 | 대기 중 이어서 작업할 수 있게 이 계획의 로컬 진행 기록을 보존한다. | 로컬 임시 파일이 남는다. |
| 2 | 지정된 클라우드 브랜치 기준을 지키고 다른 폴더의 v1.5.3을 병합하지 않는다. | 나중에 통합할 때 충돌을 해결할 수 있다. |
| 3 | 카드 서식은 공통 봉투 형식에 맞춰 `item`으로 검증한다. | 소비 코드 한 곳을 조정할 수 있다. |
| 4 | 그림을 재구성할 수 있게 선택적인 `assets`·`paintings` 맵을 함께 저장한다. | 운영 반영 전 스냅샷 형식을 조정할 수 있다. |
| 5 | 카드 서식 안의 그림도 재귀 변환하고 공유 이미지 크기 검사 함수를 제공한다. | 순수 모델의 공개 함수가 늘어난다. |
| 6 | 예상 사용량과 가져오기 카운터·시각을 처리하도록 저장소 인터페이스를 확장한다. | 실제 DB 어댑터가 이를 구현해야 한다. |
| 7 | 순수 핸들러는 사용자별로 직렬화하고 실제 DB의 잠금 연결 지점을 둔다. | 여러 서버의 원자성은 Task 5에서 별도로 검증해야 했다. 현재 검증했다. |
| 8 | 바이너리 업로드도 가져오기 토큰을 받는다. | 전송 어댑터의 추가 옵션을 유지한다. |
| 9 | JSON과 별도로 바이너리 업로드와 테스트용 전송 주입을 제공한다. | 서버의 업로드 경로 해석이 이를 지원해야 한다. |
| 10 | 배포물의 금지 문자열까지 지키도록 고정된 SDK의 서버 키 감지 분기만 빌드에서 제외하고 공개 키만 허용한다. | SDK를 올릴 때 실패하도록 만든 이 어댑터를 재검토해야 한다. |
| 11 | 개별 브라우저 검사는 파일을 명시한다. 기존 npm 명령 뒤에 파일을 붙이면 전체가 실행되기 때문이다. | 개별 검증 호출 방식이 달라진다. 최종 검사는 계획의 전체 명령을 썼다. |
| 12 | 대기 계정의 모든 쓰기를 금지하므로 닉네임은 승인 후 받는다. | 대기 중에는 닉네임을 설정할 수 없다. |
| 13 | 설정 전에는 세 번째 SQL 작성·적용을 미루고 가짜 클라이언트로 UI만 만든다. | 사용량 함수 검증을 설정 후로 미뤘다. 현재 세 원문과 실제 DB 검증을 완료했다. |
| 14 | 다른 사람의 공개 덱에서는 화면 버튼과 실제 편집·되돌리기·내보내기를 함께 막는다. | 카드 파일 인터페이스에 기본 호환 옵션 하나를 유지한다. |
| 15 | 공유 사본의 그림·레이어 식별자 변환을 재사용하고 공유 UI는 별도 모듈에 둔다. | 순수 보조 함수와 UI 모듈을 유지한다. |
| 16 | 클라우드 이미지의 로컬 식별자를 행 ID로 만들고 계정별 캐시·미완료 저장을 보관한다. | 로컬 캐시 ID가 스냅샷 ID와 다르다. 서버 내용은 명시적으로 저장할 때 바뀐다. |
| 17 | 알려지지 않은 그림 참조가 저장되지 않게 그림을 먼저 업로드한다. | 계획 예시와 진행 표시 순서가 다르다. |
| 18 | PC 일괄 가져오기는 클라우드 캐시가 아닌 PC 이미지 보관함을 읽는다. | 로컬 보관함을 읽는 함수 하나를 유지한다. |
| 19 | 최초 가져오기는 편집을 가로막는 자동 창 대신 닫을 수 있는 배너로 제안한다. | 배너를 놓치면 클라우드 메뉴에서 열어야 한다. |
| 20 | 사용자가 준비한 DB를 Task 3에서 초기화하지 않고 적용된 SQL을 검사한다. | 이 단계만으로 빈 DB 재적용은 증명하지 못했다. Task 14의 별도 복원 검사에서 재적용을 확인했다. |
| 21 | SQL 원문을 바꾸지 않고 서버 DB 트랜잭션과 사용자별 잠금으로 저장을 원자화한다. | 운영 환경도 지원되는 DB 연결·세션 풀러가 필요하다. 자격 증명은 서버 환경에만 둔다. |
| 22 | API 게이트웨이의 JWT 사전 검사를 끄고 핸들러에서 Auth `getUser`로 모든 Bearer를 검증한다. | 인증 책임이 검증된 핸들러에 있다. 일관된 오류 응답과 OPTIONS를 제공한다. |
| 23 | 모든 localhost 포트를 허용하지 않고 부록 C의 명시적 출처 목록을 따른다. | 다른 미리보기 포트는 환경 설정에 추가해야 한다. |
| 24 | 로컬 다운로드 주소용으로 공개 URL 재정의 옵션을 둔다. | 로컬 함수 실행에 비밀값이 아닌 설정 하나가 추가된다. 운영은 기본 URL을 쓴다. |
| 25 | 사용자 지정 업데이트 주소·모델 CDN 이동을 지원하도록 CSP의 HTTPS 연결을 유지한다. | 연결 목적지는 넓지만 실행 스크립트는 해시와 검증된 blob 경로로 제한한다. |
| 26 | Supabase 소유 DDL 충돌을 피하도록 앱 마이그레이션·공개/Auth 데이터와 Storage 객체를 따로 백업·복원한다. | 같은 Supabase 플랫폼 스키마가 필요하며 관련 없는 플랫폼 DDL을 교체하지 않는다. |
| 27 | 실제 로컬 UI 검사에는 별도 공개 설정·빌드 출력 경로를 쓴다. | 선택적 빌드 환경 옵션 두 개가 추가된다. 정식 설정과 기본 출력 경로는 유지한다. |
| 28 | 운영 OAuth·운영 복원·배포는 확인했다고 주장하지 않고 사용자 확인 전까지 보류한다. | 운영 반영이 대기한다. |
| 29 | 공개된 자료는 앱 밖에서도 API로 읽을 수 있다는 설계를 유지한다. | 공개 데이터의 비밀 보장은 할 수 없다. |
| 30 | 부록 A와 문서화한 어댑터를 유지하고 리뷰에서 재현된 실제 동작 결함을 고친다. | 어댑터를 앱에서 계속 관리해야 한다. |
| 31 | 비동기 쓰기는 시작한 계정에 묶고 계정 변경 시 이전 덱의 저장을 막는다. | 다른 계정으로 바꾸면 내 작업을 열거나 새 덱을 만든 뒤 저장해야 한다. 이전 편집은 로컬에 남긴다. |
| 32 | 아직 어디에도 연결하지 않은 업로드도 이미지 한도에 예약한다. | 연결·정리 전에는 실제 한도 차단이 원문 `my_usage()`의 실사용 표시보다 먼저 올 수 있다. 휴지통·이력에 연결된 그림은 이 예약에서 제외한다. |
| 33 | 기존 서버 전용 감사 표에 삭제 재시도를 남기고 객체 삭제 전에 메타데이터를 사용 불가로 확정한다. 쓰기와 정리는 공유·배타 잠금으로 조율한다. | 재시도 전까지 기록이 남고, 유지되는 DB 세션이 필요하며 정리 중 쓰기가 잠시 대기한다. |
| 34 | 일정한 키 순서로 목록을 나눠 읽고 실제 DB 구독 준비 시 한 번 더 조회한다. | 큰 목록에는 추가 요청과 구독 준비 후 조회 한 번이 필요하다. |
| 35 | 반복 검증을 위해 Task 15의 두 프로필 시나리오를 실제 Edge·Auth·API·Realtime·화면 조작으로 자동화하고 스크린샷도 살핀다. | Google OAuth와 운영 브라우저 동작은 이 로컬 증거에 포함되지 않으며 운영 확인이 따로 필요하다. |

경미한 리뷰 지적 보류: 없음.

## 보관함 통합 화면 변경 — 2026-10-22 사용자 승인

사용자가 확인한 후속 화면 구성으로 별도 클라우드 버튼을 없애고 에셋 보관함에 이미지·내 자료·공개 자료·휴지통을 모았다. 덱과 독립 에셋을 같은 목록에서 검색·필터하고, 내 계정 설정에서 기존 로그인·닉네임 변경·승인 상태·사용량·로그아웃·PC 가져오기를 관리한다. 저장 충돌과 실패 표시는 작업 화면에 유지하고 누르면 계정 설정을 연다. 승인 후 닉네임이 표시되는 기존 동작을 유지하며 닉네임 정책과 서버 권한은 바꾸지 않는다.

모바일은 전체 화면 보관함에서 목록↔상세로 이동하고 검색·종류·목록 위치를 유지한다. 작업 화면에는 저장과 보관함을 바로 배치하고 주요 터치 영역을 48px 이상으로 둔다. 그림만 고르는 기존 선택 창은 이미지 기능에 집중한다. 파일 실행·오프라인 저장·그림 자르기·카드와 A4 인쇄 색은 기존 경로를 유지한다. SQL 원문과 권한 행렬은 변경하지 않는다.

참고한 공식 UI 자료: [Apple 검색 필드](https://developer.apple.com/design/human-interface-guidelines/search-fields), [Apple 시트](https://developer.apple.com/design/human-interface-guidelines/sheets), [Android 터치 영역](https://support.google.com/accessibility/android/answer/7101858?hl=en-GB). 검색은 목록 가까이에 두고 위치와 자료 종류를 구분하며 모바일에서 목록과 상세의 뒤로 가기를 제공한다.
